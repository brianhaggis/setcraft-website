What's New in Setcraft

August 19, 2026 Current

Version 1.6.1
  • Set and show times show the exact total, with an asterisk when some songs are counting at the 5:00 default instead of the word "(estimated)". The arithmetic was always exact; it was being rounded to whole minutes on the way to the screen, throwing away seconds the set really has. Hovering the total still lists the songs that need lengths.
  • The "played here" tag is gone from library cards. The tint already says a song was played at this venue, and the words were long enough to squeeze song titles into an ellipsis on cards carrying a key, capo, tuning and length. Nothing else about venue memory changed.
  • The setlist's "Copy to upcoming show..." button is now "Copy to...", so the row of buttons above your setlist stops wrapping onto a second line. Its tooltip still spells out what it does.
  • Report a bug moved off the screen edge. The tab that sat pinned to the right of every screen is now part of beta builds only. Every copy still has Help > Report a Bug, which opens the same form.

August 18, 2026

Version 1.6.0
  • A song can appear more than once in a setlist. An encore reprise plays a song a second time, and Setcraft used to silently refuse the second copy. Each copy is now its own slot: removing one removes only that copy, dragging one between sets moves only that copy, and the tech cue sheet keeps separate FOH and lighting notes for each. The builder library still hides songs already in the setlist by default; a new checkbox under the filters shows them instead, marked with an "In set" tag and a copy count.
  • Songs can have lengths, and sets show running times. A gig is booked as time on stage, and whether the set fits its slot is easier to fix at home than at the venue. There is a Length field in the song editor (4:30, or plain minutes) and a Length column in Add Multiple. Each set header and the setlist header show a running total. The total adds up the real lengths plus 5:00 for each song that has none, so it reads "48:30" when every song has a length and "52:30 (estimated)" when any song is counting at the default; hovering it lists the songs without lengths. A max-length slider in the library filters hides songs longer than the handle, and unset songs show an italic ~5:00 tag.
  • Bandsintown can import your past shows. Setcraft can answer what you played the last time you were at a venue, but only as far back as its records go. Both sync paths gain an "Also import past shows (your full show history)" checkbox. Shows you entered by hand are matched by date and venue and linked instead of duplicated, and duplicate checking is now scoped per artist. Past shows without setlists appear in the builder's past dropdown as "(no setlist yet)" so what you played can be entered after the fact. The shows page shows long histories 50 at a time with a Show more button; search still covers every show. This also fixes a bug where "Build Setlist" on a past show card led to a locked builder with no explanation.
  • Songs can carry a recording (paid and trial). A recording answers two questions the song's fields cannot: how long the song actually runs, and how it sounds next to another one. An Audio button on each library row attaches an MP3, M4A, FLAC, WAV, or AIFF up to 100 MB. Attaching fills in the song's length from the file (a one-time dialog asks which to keep if they disagree). Audio stays on this Mac: portable backups do not include it, and the backup screen says so.
  • Transition previews (paid and trial). How a set flows depends on how one song hands off to the next, and until now the only way to check a transition was rehearsal. A Preview Transitions button in the builder opens a per-set view. A play control between two songs with audio plays the last ten seconds of one into the first ten of the next. Songs without audio can be attached from the same view.
  • Between-song notes can carry a time. Stage talk takes time the same way songs do. A note like band intros or a retune can be given a length, and that time counts toward the set total. Notes without a time count as zero and never make a total estimated. Saved default notes remember their time.
  • Adding notes moved into the setlist. A note belongs at one exact spot in the set, and the old panel asked you to write it first and drag it into place after. The panel is gone. Hover between two songs and click the + to add a note at that spot, drop in a saved default, or give it a time. Click any placed note to edit it. The song library now has the whole left column.
  • Fixed: editing a song from the library no longer risks blanking fields the edit form doesn't manage (lyrics and the chart file were being cleared on every save); editing an archived song no longer silently restores it; the length slider's right end always reads "Any" (songs longer than the last slider stop were invisible in the builder library).

August 4, 2026

Version 1.5.2
  • Bandsintown can now check for new shows on its own. A per-artist checkbox in Backstage → Integrations, "Check for new shows when Setcraft opens," imports any new Bandsintown dates every time the app launches. A small message reports how many arrived; when there is nothing new, nothing appears. If a check fails, the outcome shows only in Backstage next to the Bandsintown fields, along with the last-checked time. Off by default, and part of the paid version and trial like manual sync.
  • PRO reports now carry the watermark on unpaid installs, matching every other printed sheet (the free tier and the trial; paid output stays clean).
  • Deleting a setlist now also removes its show's tech cue sheet, so stale FOH and lighting notes can no longer resurface on the next setlist built for that show.
  • Replacing a chart can no longer destroy the old one. The new file is written completely before the old file is removed, so a failed upload (full disk, permissions) leaves the existing chart in place.
  • Restores refuse to run without their safety net. Both the portable backup restore and the snapshot rollback now stop, with your data untouched, if the automatic pre-restore snapshot cannot be saved.
  • Rolling back to an old snapshot no longer empties newer parts of the database. Tables added by an app update after the snapshot was taken are left as they are instead of being wiped.

August 1, 2026

Version 1.5.1
  • Databases now repair themselves on launch. Two long-standing migration bugs are fixed: an install whose preferences table held duplicate rows now merges them cleanly (the old repair failed silently every time), and an interrupted photo-counter rebuild no longer leaves the database wedged in a state it could never recover from. Both repairs were verified against deliberately broken databases.
  • Setlist photos taken sideways now import right side up. Phone cameras store portrait shots as rotated data plus an orientation tag. The analyzer now honors the tag, so a two-column setlist photographed in portrait keeps its sets in the right order instead of swapping them.
  • Onboarding polish. The setup wizard's theme previews now show each theme's real artwork instead of a flat color. Welcome dialogs wait until a tutorial tour finishes instead of covering it. The tour dims the page less. The sample band's songs no longer trigger achievement celebrations on a brand-new install.
  • The free version and trial watermark is now described accurately in the app as a watermark overlay across each page.
